# Implementation Plan and Tracking

## Scope

1. Rework to Next.js frontend + Python backend.
2. Implement material aware mapping lifecycle.
3. Seed hBN mock mapping.
4. Add sample images and tests.
5. Keep Electron desktop option.

## Delivered in this iteration

1. Backend (FastAPI)
- Material listing and mapping status endpoints.
- Mapping upload endpoint.
- Analysis endpoint with pixel + ROI outputs.
- Mapping storage model with default and uploaded layers.

2. Frontend (Next.js)
- Material selection and mapping status UX.
- Upload mapping JSON UX.
- Image upload + coordinate and ROI forms.
- Result visualization with confidence and class breakdown.

3. Data and examples
- Mock hBN mapping table in JSON.
- Synthetic microscope-like sample images generated by script.
- Mapping template for adding new materials.

4. Validation
- API tests for material listing, status, and analysis flow.

5. Desktop path
- Electron shell aligned for loading web UI URL.

## Remaining planned enhancements

1. Calibration toolkit
- Add guided calibration workflow from AFM/Raman-labeled points.
- Persist versions and calibration metadata.

2. Model-assisted mode
- Add optional classifier/regressor with confidence intervals.

3. Batch analysis
- Folder upload and CSV/JSON export with summary statistics.

4. Better substrate estimation
- Auto segment bare substrate area.

5. Dataset integration
- Add managed import for open microscopy datasets when licensing allows.

## Risks and mitigations

1. Lab-to-lab color variance
- Mitigation: explicit mapping upload and future reconstruction/calibration pipeline.

2. Mapping schema drift
- Mitigation: pydantic validation and schema documented in README.

3. Local runtime friction
- Mitigation: split setup docs by backend/frontend/desktop.
